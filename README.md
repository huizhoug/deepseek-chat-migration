# DeepSeek 对话迁移

将 DeepSeek 官网「导出数据」得到的 ZIP，导入为 **DeepSeek Harness 原生、可继续聊天的会话**。有中文界面，无需终端、Python、浏览器脚本或 DeepSeek 官网登录凭据。

这是社区开发的第三方插件，与 DeepSeek 官方没有隶属关系。

## 下载

普通用户请到 [Releases 下载页面](https://github.com/huizhoug/deepseek-chat-migration/releases/latest)，下载 `deepseek-chat-migration-1.0.2.tgz` 安装包，**不要解压**。GitHub 自动提供的 `Source code (zip)` 是开发源码，不是可直接安装的插件包。

## 安装与使用

适配并验证：**DeepSeek Harness 0.2.0-rc.2**，内置会话存储（Session format 4）。请先启动 Harness，至少建立一个工作区。

1. 打开 Harness 左侧「插件」，点击「添加插件」。
2. 在「包名或地址」输入框粘贴 `deepseek-chat-migration-1.0.2.tgz` 的**完整文件路径**，点击「安装」。macOS 可在 Finder 选中文件，按 ⌥⌘C「拷贝为路径名称」后粘贴。
3. 启用 `deepseek-chat-migration`。左侧出现「导入官网对话」；首次启用也会显示引导。若安装后入口未出现，完全退出并重新打开 Harness。
4. 在 DeepSeek 官网头像 → 设置 → 数据管理 → 导出数据，下载 ZIP。**不用解压**。
5. 打开「导入官网对话」，选择或拖入 ZIP（也支持已解压的 `conversations.json`）。预览、筛选并勾选要迁移的对话，选择目标工作区，然后开始导入。
6. 在完成结果中点击「继续聊」，即在 Harness 原生对话页面打开。后续回答使用 Harness 当前配置的模型和权限设置；导入本身不调用模型 API。

插件是本地安装包，尚未发布到 npm；不能只输入包名从市场搜索安装。无需运行 `npm install` 或配置 skill。

## 从 1.0.0 / 1.0.1 升级到 1.0.2

1.0.2 新增迁移结果清理与本次导入会话的永久删除，同时保留 1.0.1 的侧栏标题修复。已有对话可以直接修复标题，不用重传 ZIP、逐条打开对话或调用付费模型。

1. 等当前导入、标题修复或清理完成；导入任务也可以点击「停止导入」并等待停止。
2. 打开左侧「插件」，在「已安装」中点击 `deepseek-chat-migration` 的卡片，进入详情后点击「卸载」并确认。
3. 返回「插件」，点击「添加插件」，在「包名或地址」粘贴新版 `deepseek-chat-migration-1.0.2.tgz` 的完整路径，点击「安装」，然后启用插件。
4. 完全退出并重新打开 Harness，确保新版生效。打开左侧「导入官网对话」，等页头「正在修复已导入的侧栏标题…」完成，原来的侧栏会话列表会自动刷新。

在已验证的 Harness 0.2.0-rc.2 中，按官方插件页面卸载只移除插件包和启用配置，**会保留原生会话、插件暂存、任务及去重记录**；升级继续使用同一 Harness 数据目录即可。[官方卸载实现](https://github.com/deepseek-ai/deepseek-harness/blob/v0.2.0-rc.2/packages/boot/plugin-manager/src/index.ts)调用 profile 内的 `pnpm remove`，本插件退出时也不会清除这些数据。

新版每次启动会自动检查迁移记录中的已导入会话，补齐侧栏标题。修复以会话当前的原生记录为准，保留你后来修改的标题和继续聊天的内容；已删除的会话会跳过，不会重新创建。页面有迁移记录时，也可以点击页头「修复已导入标题」手动运行；部分失败时点击「重试标题修复」。修复期间先等待完成，再开始新的导入。

## 会保留什么

- 原标题、原创建时间、用户和助手正文、消息顺序、代码和公式的原始文本。
- 可选择保留思考内容，界面默认关闭；保留导出中提供的搜索引用与附件名称。
- 同一对话的多个叶子分支，默认分别导入，并在标题注明分支。也可只导入按消息时间判断的最新分支；官网导出不提供当前选中分支，因此不把「最新」当作「当前」。
- 原始对话作为正式模型历史进入 Harness。很长的历史仍受所选模型的上下文长度和 Harness 的压缩策略限制。

官网导出通常只有 `conversations.json` 和 `user.json`，**没有附件原文件**。本插件会明确标注附件内容未迁移；不会伪造文件、网页工具执行结果或引用中未提供的内容。只有思考、没有回复的原消息也会保留并说明。未识别或损坏的记录会显示警告，正常对话可以继续迁移。

## 重复导入、取消和恢复

相同内容、目标工作区及思考选项再次导入会跳过已完成分支；先导入最新分支、再导入全部分支也不会重复该分支。导出有新增内容、改用另一个工作区或改变思考选项时，会生成新的会话副本，不改写已导入后继续聊天的记录。

取消会等待当前完整会话写入完成，再停止后续会话。失败、中断和取消后的任务可以重试。进度和去重记录保存在本机，重启后可恢复。导入完成后可下载不含对话正文的 JSON 报告。

在页面「删除本机暂存」只清除该份导出的本地副本，不会删除已经导入 Harness 的对话；已有去重记录和任务报告保留。若先移除了导出文件，再要重试任务，请重新选择同一 ZIP。

## 清除迁移结果或删除本次导入会话

导入结束后的「会话结果」区提供两种操作，都会先要求确认：

- **清除这次迁移记录**：移除当前这次任务的结果列表与报告。已导入的原生会话、去重记录和本机上传暂存均保留；清除后的任务记录无法恢复。
- **删除本次导入会话并清除记录**：按当前这次结果中唯一的已导入会话标识永久删除原生会话，**包括后来在这些会话中继续聊天的内容和修改的标题**。确认框会显示涉及的会话数量。全部删除成功后，清除本次迁移记录及这份本机上传暂存；不会修改 Downloads 等目录里的原始 ZIP，也不会删除不属于本次迁移结果的会话。被删除的原生会话及后续聊天记录无法恢复。

永久删除是实际移除原生会话存储，和 Harness 的「归档会话」不同。当前仅针对 **Harness 0.2.0-rc.2 的内置 JSONL 会话存储、macOS / Linux** 提供；已在 macOS 验证，Linux 尚未实测。Windows 可以清除迁移记录，暂不提供原生会话永久删除。其它存储后端和不兼容版本会拒绝删除。

仍被 Harness 打开、持有或运行中的会话会拒绝删除。请先关闭该会话或完全退出并重新打开 Harness，再点击「重试清理」。部分失败时保留任务记录和上传暂存，显示每条结果及失败原因；成功删除的会话不会再次出现「继续聊」。清理进行中不能同时导入、修复标题、删除暂存或再次清理。中断后可重试清理。

已有部分会话删除、批次尚未完成时，请先点击「重试清理」完成原批次，再开始新的导入、导入重试或清除其它迁移记录；期间仍可修复标题、选择上传文件，原批次的重试入口会保留。

清理完成后，当前窗口的侧栏会自动刷新。使用同一数据目录的其它 profile 或窗口可能保留旧的列表视图，需要刷新或重启；不要在其它实例仍打开这些会话时执行删除。

## 本地数据与兼容性

文件通过 Harness 自身认证通道进入本机插件，不上传第三方服务。插件不读取 `user.json`，不读取官网账号密码、Cookie 或 API key。原始 `conversations.json`、任务和去重记录保存于 `$DSH_HOME/plugin-data/deepseek-chat-migration`（默认 `~/.dsh/plugin-data/deepseek-chat-migration`）；POSIX 下目录权限 700、文件 600。Windows 使用当前用户目录权限。

原生会话由 Harness 官方存储 API 写入；导入不会改写已有会话。永久删除是针对已验证内置存储实现的清理操作，按迁移记录验证会话范围后删除，拒绝仍被持有的会话。对不兼容的会话格式或非内置存储后端，页面显示兼容性原因并阻止导入。尚未验证未来 Harness 版本；升级前请确认插件兼容版本。

这是一次文件迁移。官网继续产生的新消息需要重新导出、重新导入，不是双向实时同步。同一 Harness 数据目录同时运行多个实例时，只允许一个实例启用迁移写入；第二个实例会显示提示，请关闭另一个实例后重新启用插件。

## 开发与验证

需要 Node.js 22.19+ 或 24+。

```sh
npm ci
npm run typecheck
npm test
npm run pack:release
```

Host 和 Client 分开做 TypeScript 检查，避免 Harness 的双端 Cordis 类型混用。Host 使用官方 Connection Fetch 路由，桌面 IPC 与 Web 使用同一个认证入口；Client 使用 Harness 原生 slots、工作区和会话导航。

测试包含 ZIP 损坏/路径/体积限制、真实导出结构与分支、正文转义、取消与重试、去重和重启恢复；使用正式 Harness none/zstd 存储验证会话，并用实际 AgentLoop 与离线模型验证后续请求包含原历史。运行完整真实导出验收时显式提供文件路径，数据只写临时隔离目录并自动清理：

```sh
DEEPSEEK_EXPORT='/absolute/path/deepseek_data.zip' node scripts/harness-smoke.mjs
```

架构：`archive.ts` 解析导出 → `engine.ts` 管理任务和持久去重 → `harness.ts` 写入正式会话；`http.ts` 负责受认证的请求协议，`client.tsx` 提供原生界面。源码和测试中不包含用户导出内容。

官方参考：[Harness 源码](https://github.com/deepseek-ai/deepseek-harness)、[插件说明](https://github.com/deepseek-ai/deepseek-harness/blob/v0.2.0-rc.2/docs/subsystems/plugins.md)、[官网数据导出说明](https://cdn.deepseek.com/policies/zh-CN/deepseek-privacy-policy.html)。
